Simple Balance {{ .Chart.AppVersion }} is installed as {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

Three workloads: {{ $serverName }} (API and MCP), {{ $frontendName }} (browser
bundle and the proxy in front of the API), {{ $schedulerName }} (recurrences).

1. Watch them come up. The API and the scheduler both run the migrations under
   an advisory lock on first start, so the first rollout takes as long as the
   migrations do and readiness stays closed until they finish:

     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ $serverName }}
     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ $frontendName }}
     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ $schedulerName }}

   A pod stuck not-ready is nearly always the database: the role in DATABASE_URL
   needs CREATEDB if the database it names does not exist yet.

     kubectl -n {{ .Release.Namespace }} logs deploy/{{ $serverName }}

{{ if .Values.ingress.enabled -}}
2. Point DNS at your ingress controller for {{ .Values.ingress.host }}, and make
   sure the {{ if .Values.ingress.tls.issuer }}Issuer {{ .Values.ingress.tls.issuer }}{{ else if .Values.ingress.tls.clusterIssuer }}ClusterIssuer {{ .Values.ingress.tls.clusterIssuer }}{{ else }}TLS secret{{ end }} exists. Then:

     kubectl -n {{ .Release.Namespace }} get ingress {{ $fullname }}

     kubectl -n {{ .Release.Namespace }} get certificate

   The site answers on https://{{ .Values.ingress.host }}/ once the certificate
   is ready.
{{- else }}

   The site answers on http://{{ .Values.ingress.host }}/.

3. Claim the first account at {{ .Values.config.appBaseUrl }}/.

{{ else }}

{{- if and .Values.config.trustProxy .Values.ingress.enabled (eq (include "simple-balance.trustedProxies" .) "127.0.0.1") }}

WARNING: every sign-in attempt in this cluster counts against one allowance.
The frontend's nginx tells the API which address a request came from, and behind
an ingress that terminates TLS that address is the ingress — the same value for
every visitor. With config.trustProxy on and frontend.trustedProxyCidr left at
its off position, four wrong passwords from anywhere lock everyone else out.

Set frontend.trustedProxyCidr to the pod CIDR your ingress controller runs in:

  --set frontend.trustedProxyCidr=<ingress controller pod CIDR>

Name the controller's range and nothing wider. This decides whose word is taken
for a visitor's address, so a range that includes callers lets a caller choose
their own. Behind a chain of proxies that each append to X-Forwarded-For, such
as Google's load balancer where it is the ingress, list every hop's range and
set frontend.realIpRecursive=true:

  --set 'frontend.trustedProxyCidr={<range>,<range>}' --set frontend.realIpRecursive=true

A cloud load balancer in front of ingress-nginx is not such a chain: ingress-nginx
replaces the header with the address it saw unless use-forwarded-headers and
compute-full-forwarded-for are both on, so the frontend sees one entry, the load
balancer's. Fix that at the ingress, with proxy protocol as the aws Pulumi
program does, and leave recursion off.
{{- end }}

Database connections. This release peaks at {{ $serverPeak }} API and {{ $schedulerPeak }} scheduler
replicas, each holding {{ $pool }} connections and one more while it starts:

  ({{ $serverPeak }} + {{ $schedulerPeak }}) x ({{ $pool }} + 1) = {{ $peakConnections }}

against a max_connections of {{ $maxConnections }}{{ if not .Values.database.enabled }}, which is PostgreSQL's default{{ else }}, which this chart sets on the cluster it runs{{ end }}. Lower
config.databasePoolSize before raising a replica count, or put a pooler in front
and set secret.directDatabaseUrl so migrations and the first-account claim go
past it.
{{- if gt $peakConnections $maxConnections }}

WARNING: {{ $peakConnections }} is past that. Scaled all the way out, replicas will fail
to connect rather than queue. Raise max_connections to suit, or lower
config.databasePoolSize, or lower the replica ceilings.
{{- end }}
{{- if .Values.secret.existingSecret }}

Credentials come from the existing Secret {{ .Values.secret.existingSecret }}. Every key in it
is handed to the API and the scheduler as an environment variable, so it must
carry {{ if not .Values.database.enabled }}DATABASE_URL and {{ end }}AUTH_SECRET, whichever of DIRECT_DATABASE_URL,
GOOGLE_CLIENT_SECRET, SMTP_USERNAME, SMTP_PASSWORD, SETUP_TOKEN, METRICS_TOKEN,
STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET apply, and nothing but settings the
server reads.
{{- if .Values.database.enabled }}

DATABASE_URL is not one of them. This release runs the database, so the string
is derived from the password it generated and put in {{ include "simple-balance.ownSecretName" . }},
which the pods read first; a DATABASE_URL in {{ .Values.secret.existingSecret }} would be read
second and would win, pointing the application at a database this cluster is not
the one running.
{{- end }}
{{- end }}
{{- if .Values.database.enabled }}

This release runs its own PostgreSQL: {{ add1 (int .Values.database.workers) }} Citus group(s) of
{{ .Values.database.replicasPerGroup }} replica(s), with Patroni doing the failovers.

  kubectl -n {{ .Release.Namespace }} get statefulset -l app.kubernetes.io/component=database
  kubectl -n {{ .Release.Namespace }} exec -ti {{ include "simple-balance.databaseGroupName" (dict "root" . "group" 0) }}-0 -- patronictl list

The application reaches it with sslmode=verify-full against a CA this chart
generated and keeps in {{ include "simple-balance.databaseSecretName" . }}. That Secret is the
cluster's identity as well as its passwords: back it up with the data, because a
restored volume and a regenerated CA do not know each other.
{{- if not (include "simple-balance.databaseSynchronous" .) }}

NOTE: commits do not wait for a standby, so a failover can lose the last few
transactions — for a ledger, that is the books disagreeing with what somebody
was shown. That is the trade the one-node-per-service shape makes. Raise
database.replicasPerGroup to 2 and set database.synchronousReplication=true to
take the other one.
{{- end }}
