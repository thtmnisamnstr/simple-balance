# 0.2.1 acceptance

What is proven, how, and what is not. One row per area, each naming the evidence
that closes it — or saying plainly that nothing closes it yet.

This page exists because the alternative kept happening: a release verified by a
list of activities rather than a list of claims, where "we tested the billing
flow" reads as closed and means somebody clicked through it once. A row here is
closed only by something a person can re-run.

**Read the last section first if you are deciding whether to cut.** Eight things
are outstanding and three of them are gates.

## Outstanding

Three are gates you set. One is a limit of what has been measured. Four are
known and recorded rather than fixed, each with its reason. None should be
reported as closed.

| Area | What is not proven | Why it is still open |
| --- | --- | --- |
| **Stripe, against a real account** | The subscription schedule path, 3-D Secure — including "Pay now" on a `past_due` subscription and the invoice an uncollected upgrade hands back — proration arithmetic, which invoice reactivates an `unpaid` subscription, whether the card-pinning fix recovers a `past_due` subscription, a Link sign-in, and Google Pay's popup under the plan tab's opener policy | No live Stripe account exists. The host list is no longer a guess: the policy is Stripe's published Stripe.js set plus its Link set, plus four additions each named in `src/server/http-security.ts` — `*.hcaptcha.com`, `m.stripe.com`, `q.stripe.com` and `errors.stripe.com`. Which of those four a live account actually contacts has not been observed, and `SB_CSP_REPORT_ONLY` is how an operator finds out without enforcing anything |
| **Ads, against a real account** | No AdSense unit has ever rendered, and the ads policy — derived from how Google documents its tag and its consent message — has never been seen holding one, nor has the consent message under the referrer policy those pages now send. Account approval, site verification and the European regulations message are the operator's and have not been done for a test deployment either | No AdSense account exists |
| **The cloud programs** | `deploy/pulumi/aws-single/` has not been applied, and none of `aws/`, `gcp/` or `oci/` has deployed the chart — `oci/` is the newest and has only ever been planned, twenty-one resources through to the chart release, against a real tenancy. So nothing has watched the visitor's address arrive at the API behind a real load balancer: the NLB's proxy protocol v2, its port-80 health check and where it places its nodes on AWS, and container-native load balancing and the appended header on GCP. `oci-single` has been applied and is the Closed row above, but two of its refusals were never reached on the way through: the data volume's `protect` flag actually turning back a `pulumi destroy`, and the availability-domain mismatch. Nor has `aws-single` run against a live account, nor `verify-full` against a real OCI Database with PostgreSQL or Amazon RDS. And the stack's settings have never been fetched from a real store: the OCI Vault secret, the dynamic group and policy that let the application node read it with its instance principal, the Secrets Manager secret and its role grant, and the two pinned CLI images run on a machine against them. The fetch script is held against a fake CLI by `tests/systemd-scripts.test.ts` and the commands against the real images' help; how long a new OCI grant takes to be honoured, which the first boot waits up to ten minutes for, has not been observed. On OKE specifically, nothing has watched a node join: `tests/cluster-control-plane.test.ts` asserts the API endpoint's subnet admits 6443 and 12250 from the workers, which is the precondition a preview cannot check and whose absence looks like a bad image rather than a firewall | No cloud accounts with quota. What stands in for them is vendor documentation, ingress-nginx's source, Pulumi's mocks, and stock nginx and PostgreSQL built into each chain; for `aws-single`, the real AWS provider (7.45.0) driving a stand-in of the program's graph against a moto server, which is where its region and teardown behavior was observed. `tests/ha-client-address.test.ts`, `tests/frontend-real-ip.test.ts`, `tests/oci-single.test.ts` and `tests/aws-single.test.ts` hold the programs' shape and not the clouds' behavior |
| The `ha` cluster, on a cloud | It has run on kind, where storage is local and a node is deleted politely rather than disappearing | Follows from the row above. 0.2.1's two OKE changes — the StorageClass replaced under its own name, and in-transit encryption on the node pool — have been planned in code only; whether replacing the class makes Pulumi re-plan the chart release is worth a `pulumi preview --diff` on a real cluster before a stack upgrades |
| Parity, one level down | Everything an agent can set, a person can | Not all of it yet, and `tests/mcp-parity.test.ts` names each gap with a reason that is now true rather than one that argued the gap away: retuning a budget's rule within its kind (a fund's target and date, a lookback, a step, an income share) has no control in the edit dialog; the template mass edit offers no destination amount, no free-text category and no way to clear a type; it leaves out a date and a split on purpose while the tool keeps both, which only a deprecation can resolve; an agent can rewrite or clear a hand-made entry's bank reference and a person cannot; and a split whose two new categories need two different kinds can only be answered by an agent |
| Known defects, low | Nothing in the books is wrong, and each of these is a refusal or a 500 in a rare race | The recurrence sweep claims its row before the namespace locks an edit or a merge takes first, so the two can deadlock (`proposeDueOccurrences`). A staged row made from a template that was then deleted still cannot be committed. Replacing a card and choosing a plan each hold a pooled connection across the Stripe calls that charge, by design, and neither is timed by the transaction-duration metric. Enter in a category group's name commits by blurring the field, so focus falls to `<body>`. And a row menu's items inside a `.row-actions` cell inherit that cell's 7px touch overlay, so the bottom edge of one item presses the next |
| Sign-in by Google ID token | Page script cannot mint a session | `POST /api/auth/sign-in/social` still accepts a Google ID token, which `get-access-token` hands to page script, and a session minted that way is not revocable from a Google-only account. Turning it off narrows what a client could do, so it waits for a deprecation (`docs/standards/writing.md` §Versioning) |
| Costs and container limits | The cost tables price what Oracle charges, and the database container has the memory a query asks for | `docs/deployment-costs.md` prices block storage at $0.0255 a GB-month and leaves out the Balanced tier's performance units, so every storage figure is understated by about two fifths. And at `medium` and `large`, `work_mem` of 16 MB and 32 MB could ask for more shared memory on a parallel hash join than Docker's default 64 MB of `/dev/shm` gives the database container |

**On a cloud machine, the Stripe and Ads rows need a release that carries
billing and ads, and 0.2.0 is it.** Every cloud program deploys the release
image its checkout pins, which is now 0.2.0. A stack whose
`simple-balance:imageTag` names 0.1.6 runs an image that reads none of the
billing or ads settings and starts without saying it ignored them, so a Stripe
or AdSense account applied to it proves nothing.

## What this page is not

It is not a test report — the suite reports itself, and the numbers move. It is
the list of **claims** and what answers each, so that the next person to ask "is
the billing flow tested?" gets a file and a line rather than a memory.

A row moves out of Outstanding when something re-runnable closes it, never
because it was discussed.
